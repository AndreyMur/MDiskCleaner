# PRD 03 — Модуль «Сканер остатков (Leftover Scanner)»

- **Версия:** 1.0
- **Дата:** 2026-09-06
- **Относится к:** PRD 00 (G1), PRD 01 (категория Leftover)

## 1. Назначение

Поиск «остатков» удалённых программ и следов установок: папки-апдейтеры, конфиги, пустые/осиротевшие каталоги в Program Files и ProgramData, осиротевшие записи реестра. Именно эти объекты не видны в «Установке приложений», но занимают место.

## 2. Типы остатков и реальные примеры

| Тип | Примеры (реальные) | Размер |
|---|---|---|
| Папки `*-updater` в `%LOCALAPPDATA%` | lm-studio-updater, kimi-desktop-updater, pachca-updater, qwen-updater, arduino-ide-updater, nextrp-launcher-updater, @opencode-aidesktop-updater, networkserviceproxyd-updater | ~1,8 ГБ |
| Конфиг удалённой IDE | `Local\Google\AndroidStudio2025.3.2` (приложение не установлено), `.android` | ~1,1 ГБ |
| Осиротевшие папки в Program Files | `4DDiG File Repair`, `360`, `ViewPlayCap`, `Activation-Renewal`, `WondershareUpdate` — нет записей в Uninstall | 0–5 МБ каждая |
| Остатки в ProgramData | `Windows4DDiGFileRepair`, `Wondershare`, `PDFConverter`, `Windows4DDiG...` | до 400 МБ |
| Осиротевшие записи Uninstall | записи без файлов/установщика (Publisher `${PRODUCT_PUBLISHER}` и т.п.) | — |
| Windows.old / Windows.old.000 | каталоги предыдущей ОС | 30 МБ+ (часто больше) |

## 3. Алгоритм поиска (из реальной практики)

1. Собрать «белый список» установленного ПО из реестра Uninstall (InstallLocation и DisplayName).
2. Просканировать `C:\Program Files`, `C:\Program Files (x86)`, `C:\ProgramData`, `%LOCALAPPDATA%`, `%APPDATA%`, `%USERPROFILE%` на каталоги верхнего уровня.
3. Кандидат в остатки, если каталог **не сопоставлен** ни с одним InstallLocation/DisplayName из реестра.
4. Дополнительные эвристики:
   - имя содержит `updater`, `update`, `_updater`, `-updater` → остаток апдейтера;
   - конфиг-папка продукта (по справочнику брендов), у которого нет установленного приложения и нет запущенных процессов;
   - имя совпадает с брендом из ProgramData «мусорного» продукта;
   - каталог пуст или почти пуст.
5. Ручная верификация не нужна, если риск низкий; для Program Files/ProgramData — всегда подтверждение.

## 4. Функциональные требования

- FR-3.1: Сопоставление папок с реестром Uninstall (по InstallLocation и по имени) — автоматически.
- FR-3.2: Отдельная группа «Остатки апдейтеров»: маска `*-updater`, с размером и датой последнего изменения. В реальном кейсе эти папки остаются после установки приложения из инсталлятора.
- FR-3.3: Группа «Конфиги удалённых программ»: если приложение отсутствует в реестре, но есть его конфиг-каталог в AppData — предложить удаление (с проверкой процессов, PRD 05).
- FR-3.4: Группа «Осиротевшие папки Program Files/ProgramData»: предлагать удаление **только при условии**, что (а) нет записи Uninstall, (б) нет запущенных процессов из этого пути, (в) размер мал или это известный бренд. Всегда требовать подтверждение.
- FR-3.5: Поиск `Windows.old*`: показывать размер, способ удаления (Storage Sense / `cleanmgr` / DISM). Удаление только с админ-правами.
- FR-3.6: Для каждого кандидата показывать «почему это остаток» (нет в реестре / updater / конфиг удалённого продукта / нет процесса).
- FR-3.7: Возможность «Добавить в исключения» путь или бренд (например, пользователь знает, что папка нужна).
- FR-3.8: Dry-run и пообъектное подтверждение (по умолчанию все кандидаты «выключены», пользователь включает).

## 5. Безопасность и риски

- Ложные срабатывания возможны для: переносимых (portable) программ, вручную распакованных SDK, папок с данными пользователя (не удалять содержимое, которое не похоже на кэш/апдейтер).
- Порог: НЕ предлагать к автоудалению папки размером > 1 ГБ без явной категории (сначала анализ содержимого).
- Папки в Program Files удаляются только из-под админа (UAC), см. PRD 05.
- Перед удалением проверять, не входит ли путь в `%PATH%` и не зарегистрирован ли как служба.

## 6. Нефункциональные требования

- Сканирование остатков — ≤ 60 секунд (не полный обход Program Files; обход только верхних уровней + сверка с реестром).
- Журнал с фиксацией основания удаления.

## Стек и реализация (в рамках PRD 00)

- Белый список установленного ПО — из реестра (сервис PRD 01); сопоставление папок по `InstallLocation` и нормализованному `DisplayName` (FR-3.1).
- Обход — только верхние уровни (`GetDirectories`) в `Program Files`/`Program Files (x86)`, `ProgramData`, `%LOCALAPPDATA%`, `%APPDATA%`, `%USERPROFILE%`; цель — ≤ 60 с, без полного рекурсивного обхода (NFR).
- Правила кандидатов — движок эвристик `LeftoverRuleEngine`: маска `*-updater`, справочник брендов, «пустые каталоги»; результат — `LeftoverCandidate` с полем «основание» (FR-3.2–3.6).
- Проверки перед удалением — запущенные процессы (`System.Diagnostics.Process`, WMI), вхождение в `%PATH%`, регистрация службы (`sc query` / `ServiceController`) (FR-3.3–3.4, §5).
- Исключения пользователя — JSON `%LOCALAPPDATA%\DiskCleaner\exclusions.json` (FR-3.7); dry-run и «всё выключено по умолчанию» — модель плана из PRD 00 (FR-3.8).
- Удаление из Program Files/ProgramData и Windows.old — через elevated-процесс (см. PRD 05).

## 7. Критерии приёмки

- На эталонной машине находит все 8 updater-папок (~1,8 ГБ) и конфиг Android Studio.
- Не предлагает удалить ни одну папку действующего приложения (проверка по контрольному списку установленного ПО).
- Корректно требует админ-права и подтверждение для Program Files/ProgramData.
