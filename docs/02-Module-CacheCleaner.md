# PRD 02 — Модуль «Кэш-клинер»

- **Версия:** 1.0
- **Дата:** 2026-09-06
- **Относится к:** PRD 00 (G2, G3), PRD 01 (категория Cache)

## 1. Назначение

Безопасная очистка кэшей пакетных менеджеров, тулчейнов и приложений. Все объекты этой категории регенерируются автоматически, поэтому риск низкий, но модуль обязан предупреждать о последствиях (трафик, время повторной загрузки).

## 3. Ключевой урок (переносим в требования)

Реальный `npm config get cache` указывал на `D:\npm-cache`, а `C:\Users\Andrey\AppData\Local\npm-cache` (14,5 ГБ) был **осиротевшим остатком** прежней конфигурации. Поэтому:
- FR-2.2: всегда определять фактический путь кэша через конфиг менеджера, а не по умолчанию;
- FR-2.3: если фактический путь вне сканируемого диска — показать объект отдельно и предложить очистку там же;
- FR-2.4: уметь чистить «осиротевший» кэш по известному пути, даже если менеджер его больше не использует.

## 4. Функциональные требования

- FR-2.1: Группировать кэши по менеджеру/приложению с оценкой размера из PRD 01.
- FR-2.5: Для каждого кэша показывать: штатная команда (если есть), оценка экономии, «что произойдёт после очистки» и сколько времени/трафика нужно на восстановление.
- FR-2.6: Приоритет использования **штатной команды** (`npm cache clean --force`, `uv cache clean`, `pip cache purge`, `rustup self uninstall`), прямой удаление каталога — как fallback, если команда не очистила (реальный кейс: `npm cache clean` вернул 0, но каталог не уменьшился).
- FR-2.7: После штатной очистки перепроверять размер; если он не изменился/изменился незначительно — предлагать прямое удаление каталога.
- FR-2.8: Перед удалением проверять, что каталог не используется (см. PRD 05, проверка процессов); при использовании — помечать и откладывать.
- FR-2.9: Каталоги `*-updater` и конфиги удалённых приложений — в категорию Leftover (PRD 03), здесь не показывать.
- FR-2.10: VS Code: удалять только перечень кэш-подпапок (Cache, CachedData, CachedExtensionVSIXs, Crashpad, GPUCache, logs, WebStorage); никогда `User/`, `extensions/`, `settings.json`. Если VS Code запущен — отложить и предупредить (реальный кейс).
- FR-2.11: Для Gradle разбивать `caches`, `wrapper\dists`, `jdks`, `daemon` по отдельности с разным уровнем согласия.
- FR-2.12: Включить режим «не трогать кэши, если на диске < 15% свободного места» (защита от избыточной очистки без необходимости).

## 5. Права и UAC

- Кэши пользователя (`%LOCALAPPDATA%`, профиль) не требуют админа.
- `rustup self uninstall` — запуск в контексте пользователя.
- Если менеджер глобальный (установлен в Program Files) — повышение при выполнении команды.

## 6. Нефункциональные требования

- Удаление каталога 14 ГБ — не дольше 3 минут; использовать быстрые API удаления, показывать прогресс.
- Никакой «тихой» очистки без отметки пользователя в UI (чекбокс по каждому объекту).
- Сухой прогон и полный журнал (что удалено, что пропущено, причина).

## Стек и реализация (в рамках PRD 00)

- Справочник кэшей — конфигурация (JSON/embedded) на менеджер: дефолтные пути, команда определения реального пути (`npm config get cache`), штатная команда очистки, «прямой» путь удаления, подпапки VS Code/Gradle и уровень согласия (FR-2.1, 2.10–2.11).
- Определение фактического пути кэша — запуск команды менеджера через `Process` (`ProcessStartInfo` с аргументами, без шелл-строк, `RedirectStandardOutput`, UTF-8) либо чтение конфига (`.npmrc`), FR-2.2.
- Штатная очистка — `Process` с перехватом exit-кода и вывода; после неё повторное измерение размера и, при незначительном уменьшении, предложение прямого удаления (FR-2.6–2.7).
- Прямое удаление каталога — `Directory.Delete(path, recursive: true)` с предварительной проверкой процессов (см. PRD 05) и прогрессом; для больших каталогов (> 1 ГБ) — удаление параллельными партиями.
- Объекты, помеченные `IN_USE`, откладываются и не включаются в авто-план (FR-2.8).
- Порог «не чистить при < 15% свободного места» — проверка `DriveInfo.AvailableFreeSpace` перед формированием плана (FR-2.12).

## 7. Критерии приёмки

- Воспроизводит очистку всех кэшей эталонного отчёта с суммарным эффектом ~35 ГБ.
- Для npm определяет реальный путь (в т.ч. на другом диске) и не пытается «чистить» несуществующий кэш.
- При запущенном VS Code кэши VS Code не удаляются, пользователь получает сообщение.
- `npm cache clean --force` с exit 0, но неизменившимся размером → предлагается прямое удаление каталога.

## 8. Открытые вопросы

- Политика по пакетным кэшам в CI/оффлайн-сценариях (запрет очистки по конфигу).
