# PRD 04 — Модуль «Деинсталлятор и очистка реестра»

- **Версия:** 1.0
- **Дата:** 2026-09-06
- **Относится к:** PRD 00 (G2, G3), PRD 01 (категории InstalledApp/DevToolchain)

## 1. Назначение

Безопасное удаление установленного ПО и SDK: выбор объектов (в т.ч. дублей и старых версий), корректный вызов штатных деинсталляторов, разбор пакетных установок (bundles) и зачистка осиротевших записей реестра.

## 2. Реальные кейсы (обязан воспроизводить)

| Кейс | Что делали | Результат |
|---|---|---|
| Две версии Windows SDK (26100 и 19041) | оставили 26100; удалили 19041 | +~2 ГБ |
| Пакетный (bundle) SDK: `winsdksetup.exe` | `msiexec /x {code}` → для родителя exit 1605; правильный путь — штатный uninstaller `winsdksetup.exe /uninstall` | все компоненты и записи реестра удалены |
| 47 MSI-компонентов SDK 19041 | `msiexec /x {GUID} /qn /norestart` по каждому | удалены |
| Дочерние ARP-записи бандла | `msiexec /x` возвращал 0, но записи/файлы оставались | повторный прогон + удаление осиротевших папок версии |
| CCleaner (Inno) на D:\ | `Uninstall.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART` | удалён |
| K-Lite Codec Pack (Inno) | `unins000.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART` | удалён |
| 4DDiG (без записи в реестре) | удаление папок `Program Files\4DDiG File Repair`, `ProgramData\Windows4DDiGFileRepair` | удалено |
| Дубли Java JDK 24/26, VS Build Tools 2019/2022 | предложить удаление старой | на усмотрение пользователя |

## 3. Функциональные требования

### Выбор объектов
- FR-4.1: Список ПО из реестра (3 ветки) с размером, датой, версией, издателем, реальным путём.
- FR-4.2: Авто-детект дублей и «старых версий»: правило «держать последнюю, удалять старые» — только как рекомендация с пометкой, никогда не предвыбор.
- FR-4.3: Пометка записей с аномалиями: пустой Publisher, `${PRODUCT_PUBLISHER}`, подозрительные домены (networkserviceproxyd/ilovehackit.ru), дата установки = дата первого запуска — группа «Проверить вручную».
- FR-4.4: Показ «занимает на C:» (InstallLocation на C:, EstimatedSize), раздельно от общего размера.

### Выполнение удаления
- FR-4.5: Определение типа деинсталлятора по UninstallString:
  - `MsiExec.exe /I{GUID}` / `msiexec` → `msiexec /x {GUID} /qn /norestart`;
  - Inno (`unins000.exe`) → `unins000.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART`;
  - NSIS (`Uninstall.exe`) → `Uninstall.exe /S`;
  - прочие → запуск как есть с флагом тихости, если известен; иначе открыть штатный GUI и дождаться завершения.
- FR-4.6: Обработка пакетных (bundle) установок: если `msiexec /x` возвращает 1605 (это не MSI) — искать исполняемый файл в `%ProgramData%\Package Cache\{code}\` и запускать его с `/uninstall` (для Winsdksetup — GUI, дождаться завершения пользователем).
- FR-4.7: Для MSI-компонентов SDK одной версии (общий DisplayVersion, напр. `10.1.19041.5609`) — собрать все GUID и удалять последовательно.
- FR-4.8: После деинсталляции пакета: перечитать реестр; повторно удалять компоненты, которые «вернулись» или не удалились с первого раза (реальный кейс: exit 0 при оставшихся записях).
- FR-4.9: После удаления компонентов проверять осиротевшие каталоги (Include/Lib/bin версии SDK) и удалять их, если соответствующих записей в реестре больше нет.
- FR-4.10: Для приложений без записи в реестре (4DDiG-типа): удаление каталогов с проверкой процессов; каталоги Program Files/ProgramData — только с админ-правами.
- FR-4.11: Каждый шаг — отдельное подтверждение с указанием объёма и названия; для GUI-деинсталляторов — инструкция пользователю в UI («завершите мастер»).
- FR-4.12: Перезагрузка: запрашивать у пользователя, не выполнять `msiexec /restart` принудительно.

### Реестр
- FR-4.13: Поиск осиротевших записей Uninstall (ссылаются на несуществующие пути) — отдельная группа, удаление по подтверждению. Удалять только записи под `Software\Microsoft\Windows\CurrentVersion\Uninstall` (и WOW6432Node), не затрагивая системные компоненты (`SystemComponent=1` без явного согласия).
- FR-4.14: Очистка `Package Cache` для удалённых бандлов (папка `{code}`), если бандл больше не установлен.

## 4. Права доступа
- FR-4.15: Все деинсталляции MSI и операции в Program Files/ProgramData выполняются в **отдельном повышенном процессе** (одна UAC-проверка на пачку, не на каждый компонент) с журналом в файл.
- FR-4.16: Не повышать права для HKCU-записей и пользовательских приложений.

## 5. Нефункциональные требования

- Время: удаление SDK (47 MSI) — не более ~5 минут суммарно; прогресс по компонентам.
- Журнал: exit-код каждого msiexec/деинсталлятора, время, ошибки. Коды успеха: 0, 3010; 1605/1612 — «не установлено», не считать ошибкой.
- Идемпотентность: повторный запуск плана не должен ломаться на уже удалённых объектах.

## Стек и реализация (в рамках PRD 00)

- Список ПО, дубли, аномалии — реестр и сервис нормализации из PRD 01; модель `InstalledApp` (FR-4.1–4.4).
- Запуск деинсталляторов — `ProcessStartInfo`, разбор `UninstallString` по типу: `MsiExec` → `msiexec /x {GUID} /qn /norestart`; `unins000.exe` (Inno) → silent-флаги; `Uninstall.exe` (NSIS) → `/S`; прочие — как есть/инструкция в GUI. `UseShellExecute=false`, перехват вывода (UTF-8), таймаут, сбор exit-кода (FR-4.5).
- Bundle-кейсы — перехват exit 1605 («это не MSI»), поиск exe в `%ProgramData%\Package Cache\{code}` и запуск `/uninstall` (FR-4.6); для GUI-мастеров — ожидание с таймаутом и инструкцией пользователю (FR-4.11).
- Массовое удаление MSI SDK — цикл по GUID одной версии с прогрессом по компонентам (FR-4.7); после каждого шага — перечитывание реестра для поиска «вернувшихся» записей (FR-4.8).
- Зачистка — удаление осиротевших каталогов версии (`Include`/`Lib`/`bin`) и записей Uninstall через `RegistryKey.DeleteSubKeyTree` только под Uninstall-ветками и WOW6432Node; `SystemComponent=1` — без явного согласия не трогать (FR-4.9, 4.13–4.14). Идемпотентность: повторный шаг с кодом 1605/1612 считается успехом (NFR).
- Повышенные операции — сценарий JSON → elevated-процесс `DiskCleaner.Elevated.exe` (одна UAC-проверка на пачку), журнал exit-кодов (FR-4.15–4.16).

## 6. Критерии приёмки

- На эталонной машине удаляет SDK 19041 полностью: реестр чист, папки Include/Lib версии удалены, Package Cache очищен.
- Корректно различает MSI-продукт и bundle (1605 → штатный uninstaller).
- Silent-удаление CCleaner и K-Lite завершается без GUI и без остатков записей.
- Ни один компонент актуальной версии (26100, JDK текущей и т.п.) не затронут.

## 7. Риски

- Удаление SDK/тулчейна, который нужен другим программам (VS Build Tools 2019 → SDK 19041) — предупреждение «может затронуть X» по списку зависимостей (v1.0 — статический список известных зависимостей).
- GUI-деинсталлятор, ожидающий действий пользователя: таймаут ожидания и инструкция в UI.
