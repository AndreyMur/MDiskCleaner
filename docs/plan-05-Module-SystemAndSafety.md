# Plan: Модуль «Системная очистка, безопасность и отчёт»

**PRD:** 05-Module-SystemAndSafety
**Дата:** 2026-09-06

## Согласованность с PRD

План покрывает FR-5.1–5.19, NFR (§3) и критерии приёмки (раздел 4 PRD). Модуль входит в M3 (plan-00) и переиспользует: движок исполнения плана PRD 00, детектор IN_USE и модель реестра PRD 01, зачистку остатков PRD 03, инвентаризацию ПО PRD 04 и elevated-процесс `DiskCleaner.Elevated.exe`. Планировщик/расписание и «Корзина-режим» для пользовательских данных из дорожной карты M3 вынесены за рамки этого PRD и в план не включены.

## Фазы реализации

### Фаза 1: Безопасная очистка Temp и журналирование (Tracer Bullet)

**Цель:** Минимальный путь «удалить объект → пропустить заблокированное → зафиксировать результат»: очистка временных файлов пользователя с семантикой «частично», которая не прерывает прогон. Фундамент для всех операций модуля.

**Затрагивает:** backend

**Задачи:**
- [ ] Исполнитель удаления с try/catch по элементам: `Directory.Delete`/`File.Delete` с пропуском заблокированных/недоступных файлов (IOException/UnauthorizedAccessException) без прерывания всего прогона (FR-5.1).
- [ ] Очистка содержимого `%TEMP%` пользователя; `C:\Windows\Temp` — пометка «требует админа» и перенос в админ-пачку (FR-5.1, FR-5.3, FR-5.12).
- [ ] Статусы шага: «успех» / «частично» (со списком неудалённых файлов) / «пропущен» (IN_USE, нет прав); «частично» не считается ошибкой плана (FR-5.9).
- [ ] Журнал каждого действия через Serilog: время, объект, размер, тип операции, результат, exit-код, ошибка; хранение в `%LOCALAPPDATA%\DiskCleaner\logs\*.log` (UTF-8) (FR-5.13, NFR).
- [ ] Тесты: integration на временных каталогах — один файл открыт процессом → шаг завершается «частично», прогон продолжается, журнал корректен.

**Когда готова:** Очистка Temp не падает из-за единичных заблокированных файлов (приёмка); заблокированные файлы перечислены, остальные удалены; журнал фиксирует каждое действие с полями FR-5.13.

### Фаза 2: Детектор занятости IN_USE и стратегии для «долгоживущих» приложений

**Цель:** Защита от «файл занят»: перед удалением объекта находить процессы из этого пути, помечать IN_USE и не удалять; предлагать пользователю осмысленные действия.

**Затрагивает:** backend

**Задачи:**
- [ ] Сбор списка процессов на время плана (WMI `Win32_Process.ExecutablePath`) с кэшированием; проверка принадлежности ExecutablePath удаляемому пути (FR-5.7).
- [ ] Пометка объекта `IN_USE` и отказ от удаления; возврат списка процессов для показа пользователю (кейсы: `adb.exe` в `Android\Sdk`, `Code.exe`, node) (FR-5.7).
- [ ] Стратегия для «долгоживущих» приложений (VS Code, браузеры): статус «закройте приложение и повторите» либо «отложить шаг» (FR-5.8).
- [ ] Интеграция проверки в исполнитель: перед каждым удалением объекта из любого модуля (кэши, остатки, ПО, системные) (FR-5.7).
- [ ] Тесты: integration — запущенный временный exe внутри удаляемого пути → объект IN_USE, список процессов передан, удаление не выполняется; unit — кэширование списка процессов.

**Когда готова:** Объект с запущенным процессом не удаляется (кейсы adb/VS Code/node); исполнитель получает список блокирующих процессов для показа; тесты зелёные.

### Фаза 3: UAC-группировка и повышенный процесс

**Цель:** Выполнить админ-шаги за один UAC-подъём, не передавая прав основному процессу, и корректно обрабатывать нехватку прав.

**Затрагивает:** backend

**Задачи:**
- [ ] Планировщик делит шаги плана на пользовательские и требующие админ-прав; для админ-пачки формируется JSON-сценарий (FR-5.10).
- [ ] Запуск единого повышенного процесса `DiskCleaner.Elevated.exe` (`ProcessStartInfo.Verb = "RunAs"`, manifest `requireAdministrator`) на всю пачку — без спама UAC (реальный кейс: 2 подтверждения на план) (FR-5.10).
- [ ] Elevated-процесс исполняет только переданный сценарий и пишет журнал; основной процесс прав не получает (FR-5.11).
- [ ] Детект нехватки прав (код 5 / Access Denied): шаг переносится в «требует админа», остальные продолжаются (FR-5.12).
- [ ] Тесты: unit — группировка шагов и сериализация сценария; integration — elevated-сценарий на временных объектах (эталонная машина), обработка Access Denied.

**Когда готова:** Админ-шаги эталонного плана выполняются за один UAC-подъём; при недостатке прав шаг помечается «требует админа» без прерывания остальных; основной процесс не наследует прав.

### Фаза 4: Системные операции: Корзина, SoftwareDistribution, гибернация, Windows.old

**Цель:** Реализовать системные операции очистки с безопасностью: ничего не выполняется по умолчанию, deny-список неприкосновенен, административные шаги идут через повышенный процесс Фазы 3.

**Затрагивает:** backend

**Задачи:**
- [ ] Корзина: очистка по выбранному диску (`SHEmptyRecycleBin` P/Invoke или `Clear-RecycleBin`) (FR-5.2); системный `C:\Windows\Temp` — очистка в админ-пачке (FR-5.1).
- [ ] `SoftwareDistribution\Download`: остановка службы `wuauserv` через `ServiceController`, очистка, запуск обратно — в elevated-процессе; при отсутствии прав — пометка «требует админа» и инструкция (FR-5.3).
- [ ] Гибернация: показ размера `hiberfil.sys`, `powercfg /h off` с явным объяснением последствий (отключение гибернации; быстрый запуск сохраняется), проверка exit-кода = 0 и исчезновения файла; обратимость через `powercfg /h on` (FR-5.4).
- [ ] `Windows.old*`: оценка размера; удаление только штатными средствами (Storage Sense/cleanmgr) или с админ-правами и подтверждением (FR-5.5).
- [ ] Deny-список «никогда не удалять вручную»: `pagefile.sys`, `swapfile.sys`, каталог `Windows`, `System Volume Information` — защита в исполнителе (FR-5.6). Тесты: unit — deny-список; integration — Корзина/SoftwareDistribution/гибернация на эталонной машине.

**Когда готова:** Очистка Корзины и SoftwareDistribution не падает на единичных блокировках; `powercfg /h off` даёт exit-код 0 и файл гибернации исчезает (операция обратима); Windows.old обрабатывается только штатными средствами/с админом; объекты deny-списка никогда не удаляются.

### Фаза 5: Исполнитель плана, снимок до/после и итоговый отчёт

**Цель:** Сквозное выполнение плана в безопасном порядке с отменой между шагами, снимком свободного места и итоговым отчётом (факт против плана).

**Затрагивает:** backend

**Задачи:**
- [ ] «Выполнить план» в порядке категорий: кэши → остатки → ПО → системные шаги; каждый опасный шаг — с подтверждением (FR-5.17); идемпотентность повторного запуска (NFR).
- [ ] Отмена между шагами через `CancellationToken`; текущий шаг доводится до безопасной точки останова (FR-5.18).
- [ ] Снимок до/после: свободное место диска (`DriveInfo.AvailableFreeSpace`) до и после; сравнение «оценка плана vs факт» (FR-5.15).
- [ ] Итоговый отчёт: «освобождено X ГБ», сводка по категориям (таблица), пропущенные/заблокированные объекты с причинами, предложение «повторить позже» (FR-5.14); экспорт отчёта Markdown/JSON на общем генераторе ядра (FR-5.16).
- [ ] «Кандидаты второго эшелона»: если свободного места после плана меньше ожидаемого — собрать крупные приложения, которые пользователь решил не удалять, и показать их (FR-5.19). Тесты: unit — порядок категорий и расчёт план/факт; integration — отмена между шагами, повторный запуск безопасен.

**Когда готова:** План исполняется в порядке «кэши → остатки → ПО → системные» с подтверждениями и отменой между шагами; отчёт показывает «освобождено N ГБ», пропущенные объекты с причинами и кандидатов второго эшелона; повторный запуск безопасен.

### Фаза 6: Системные шаги, блокировки и отчёт в GUI (frontend)

**Цель:** Дать пользователю контроль: системные шаги только по явному выбору, понятные предупреждения о последствиях, наглядный итоговый отчёт.

**Затрагивает:** frontend

**Задачи:**
- [ ] Системные шаги в плане: чекбоксы (по умолчанию выключены — ни один системный шаг не выполняется «по умолчанию»), описание последствий (например, гибернация: «быстрый запуск сохраняется»), инструкция «требует админа» (FR-5.3, FR-5.4, NFR).
- [ ] Блокировки: показ списка процессов для объектов IN_USE, действия «закройте приложение и повторите» / «отложить шаг» (FR-5.7, FR-5.8).
- [ ] Экран выполнения: порядок категорий, подтверждение опасных шагов, прогресс по шагам, отмена между шагами (FR-5.17, FR-5.18).
- [ ] Итоговый отчёт: «освобождено X ГБ», таблица по категориям, пропущенные/заблокированные с причинами, «повторить позже», снимок до/после, блок «второй эшелон» (FR-5.14, FR-5.15, FR-5.19).
- [ ] Экспорт отчёта Markdown/JSON из GUI (FR-5.16). Тесты: unit ViewModel-ей (чекбоксы системных шагов, отображение отчёта/процессов); e2e на эталонной машине.

**Когда готова:** На эталонной машине через GUI выполняется полный план (M1–M3): отчёт показывает «освобождено ~57 ГБ» с расхождением план/факт ≤ 10%; системные шаги запускаются только по явному выбору; для IN_USE-объектов пользователь видит список процессов.

## Критерии приёмки PRD (раздел 4) и их покрытие

- **Очистка Temp/Корзины не падает из-за единичных заблокированных файлов** — Фазы 1 и 4 (семантика «частично», try/catch по элементам), проверка в Фазе 6.
- **Объект с запущенным процессом не удаляется; пользователь получает список процессов** — Фаза 2 (детектор IN_USE) + Фаза 6 (показ списка в UI).
- **Гибернация: размер до, exit-код `powercfg /h off` = 0, файл исчезает, обратимость через `/h on`** — Фаза 4 (backend) + Фаза 6 (показ размера и подтверждение последствий).
- **Отчёт после эталонного прогона: «освобождено ~57 ГБ», расхождение план/факт ≤ 10%** — Фаза 5 (снимок до/после, сравнение) + Фаза 6 (e2e на эталонной машине).
