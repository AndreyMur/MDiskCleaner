# PRD 05 — Модуль «Системная очистка, безопасность и отчёт»

- **Версия:** 1.0
- **Дата:** 2026-09-06
- **Относится к:** PRD 00 (G3, G4, G5)

## 1. Назначение

Сквозные сервисы приложения: системные операции (Temp, SoftwareDistribution, Корзина, гибернация), проверка блокировок/занятости файлов, управление UAC-повышением, журналирование и отчёт о результате.

## 2. Функциональные требования

### 2.1 Системные операции
- FR-5.1: Временные файлы пользователя (`%TEMP%`) и системы (`C:\Windows\Temp`): удаление содержимого с пропуском заблокированных файлов (не прерывать весь прогон).
- FR-5.2: Корзина: очистка по выбранному диску (`Clear-RecycleBin`).
- FR-5.3: `C:\Windows\SoftwareDistribution\Download`: остановка службы Windows Update (wuauserv), очистка, запуск обратно; при отсутствии прав — инструкция (реальный кейс: недостаточно прав → шаг помечается «требует админа»).
- FR-5.4: Файл гибернации `hiberfil.sys` (в реальном кейсе 2,8 ГБ): показать размер, предложить `powercfg /h off` с явным объяснением последствий (отключение гибернации; быстрый запуск сохраняется). Обратная операция — `powercfg /h on`.
- FR-5.5: `Windows.old*`: оценка размера; удаление только штатными средствами (Storage Sense/cleanmgr) или с админ-правами и подтверждением.
- FR-5.6: Никогда не удалять вручную: `pagefile.sys` (реальный кейс — файл подкачки на D:), `swapfile.sys`, каталог `Windows`, `System Volume Information`.

### 2.2 Проверка блокировок (защита от «файл занят»)
- FR-5.7: Перед удалением объекта проверять: есть ли запущенные процессы, чей ExecutablePath находится внутри удаляемого пути (реальные кейсы: `adb.exe` в `Android\Sdk`; `Code.exe` — VS Code; node). Такие объекты помечать `IN_USE`, не удалять, показать список процессов.
- FR-5.8: Для «долгоживущих» приложений (VS Code, браузеры) предлагать: «закройте приложение и повторите», либо отложить шаг.
- FR-5.9: При частичном удалении (часть файлов заблокирована) — завершить шаг со статусом «частично», перечислить неудалённые файлы, не считать это ошибкой плана.

### 2.3 UAC и права
- FR-5.10: Планировщик группирует шаги на требующие админ-прав и пользовательские; для админ-шагов — единый повышенный процесс (`Start-Process -Verb RunAs`), чтобы не спамить UAC (в реальном кейсе — 2 подтверждения на весь план).
- FR-5.11: Повышенный процесс выполняет только переданный сценарий и пишет журнал; основной процесс не получает прав.
- FR-5.12: Детект отсутствия прав (код 5 / Access Denied) → перенос шага в «требует админа», продолжение остальных.

### 2.4 Журнал и отчёт
- FR-5.13: Журнал каждого действия: время, объект, размер, тип операции, результат, exit-код, ошибка. Хранение: `%LOCALAPPDATA%\DiskCleaner\logs\*.log` (UTF-8).
- FR-5.14: Итоговый отчёт пользователю: «освобождено X ГБ», сводка по категориям (таблица), пропущенные/заблокированные объекты с причинами, предложение «повторить позже».
- FR-5.15: Снимок до/после: свободное место диска до и после; сравнение с планом (оценка vs факт).
- FR-5.16: Экспорт отчёта: Markdown/JSON.

### 2.5 Выполнение плана
- FR-5.17: «Выполнить план» исполняет выбранные объекты по категориям в порядке: кэши → остатки → ПО → системные шаги; каждый опасный шаг — с подтверждением.
- FR-5.18: Возможность отмены между шагами; текущий шаг доводится до безопасной точки останова.
- FR-5.19: Если свободного места после плана < ожидаемого — показать «кандидатов второго эшелона» (большие приложения, которые пользователь решил не удалять).

## 3. Нефункциональные требования

- Ни один системный шаг не выполняется «по умолчанию» — только явный выбор (отключение гибернации и т.п.).
- Все операции идемпотентны; повторный запуск безопасен.
- Журнал и отчёты — UTF-8 (реальный кейс повреждения кириллицы в консоли).
- Процесс очистки не должен требовать перезагрузки (кроме случаев, когда это явно необходимо и подтверждено).

## Стек и реализация (в рамках PRD 00)

- Архитектура прав: `DiskCleaner.exe` (manifest `asInvoker`) + `DiskCleaner.Elevated.exe` (`requireAdministrator`). Планировщик делит шаги на user/admin; для админ-пачки основной процесс формирует JSON-сценарий и запускает elevated-процесс через `ProcessStartInfo.Verb="RunAs"`; elevated пишет журнал и exit-код, основной — только статус (FR-5.10–5.12).
- Проверка занятости — кэшируемый на время плана список процессов (WMI `Win32_Process.ExecutablePath`), принадлежность пути объекту (FR-5.7); отложенные шаги и «частично» — статусы в исполнителе плана (FR-5.8–5.9).
- Системные операции: Temp — `Directory.Delete`/`File.Delete` в try/catch по элементам (пропуск заблокированных, FR-5.1); Корзина — `SHEmptyRecycleBin` (P/Invoke) или `Clear-RecycleBin` (FR-5.2); SoftwareDistribution — остановка/запуск службы `wuauserv` через `ServiceController` в elevated-процессе (FR-5.3); гибернация — `powercfg /h off|on` с проверкой exit-кода (FR-5.4); Windows.old — только штатные средства/админ с подтверждением (FR-5.5). «Никогда не трогать» — deny-список путей (FR-5.6).
- Журнал — Serilog в `%LOCALAPPDATA%\DiskCleaner\logs\*.log` (UTF-8), поля из FR-5.13; отчёт — агрегация по категориям и сравнение план/факт через `DriveInfo.AvailableFreeSpace` до/после (FR-5.14–5.15); экспорт — общий генератор Markdown/JSON ядра (FR-5.16).
- Выполнение плана — движок из PRD 00: порядок «кэши → остатки → ПО → системные», подтверждение опасных шагов, `CancellationToken` для отмены между шагами (FR-5.17–5.19).

## 4. Критерии приёмки

- Очистка Temp/Корзины не падает из-за единичных заблокированных файлов.
- Объект с запущенным процессом не удаляется; пользователь получает список процессов.
- Для гибернации: показывается размер до, exit-код `powercfg /h off` = 0, файл исчезает; операция обратима через `/h on`.
- Отчёт после эталонного прогона показывает «освобождено ~57 ГБ» с расхождением план/факт ≤ 10%.
