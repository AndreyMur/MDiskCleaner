# Plan: Модуль «Деинсталлятор и очистка реестра»

**PRD:** 04-Module-Uninstaller
**Дата:** 2026-09-06

## Согласованность с PRD

План покрывает FR-4.1–4.16, права доступа (FR-4.15–4.16), NFR (§5) и критерии приёмки (раздел 6 PRD). Модуль входит в M2 (plan-00) и опирается на модель `InstalledApp` и нормализацию реестра PRD 01, проверку процессов PRD 01/05, категорию Leftover PRD 03 и elevated-процесс `DiskCleaner.Elevated.exe` (одна UAC-проверка на пачку шагов). Риски §7 (зависимости, GUI-мастера) учтены в задачах фаз.

| Фаза | FR | Затрагивает |
|---|---|---|
| Фаза 1 | FR-4.1 (данные), FR-4.5, FR-4.15, FR-4.16; NFR (exit-коды, журнал, идемпотентность) | backend |
| Фаза 2 | FR-4.2, FR-4.3, FR-4.4 | backend |
| Фаза 3 | FR-4.6, FR-4.7, FR-4.8, FR-4.9, FR-4.14 | backend |
| Фаза 4 | FR-4.10, FR-4.11 (логика), FR-4.12, FR-4.13; §7 (зависимости) | backend |
| Фаза 5 | FR-4.1–4.12 (GUI), приёмка silent-деинсталляции | frontend |

## Фазы реализации

### Фаза 1: Сквозное удаление MSI-продукта с контролем результата (Tracer Bullet)

**Цель:** Минимальный путь «запись реестра → команда → тихое удаление через повышенный процесс → контроль exit-кода → журнал» для одного MSI-продукта. Фундамент для всех остальных фаз модуля.

**Затрагивает:** backend

**Задачи:**
- [ ] Инвентаризация: список `InstalledApp` из трёх веток Uninstall (нормализация PRD 01) с размером, датой, версией, издателем и реальным путём (FR-4.1).
- [ ] Типизация `UninstallString` и построение команды: `MsiExec`/`msiexec` → `msiexec /x {GUID} /qn /norestart`; Inno (`unins000.exe`) → `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`; NSIS (`Uninstall.exe`) → `/S`; прочие — запуск как есть с флагом тихости, если известен, иначе GUI-профиль (FR-4.5).
- [ ] Elevated-исполнение пачки шагов через `DiskCleaner.Elevated.exe`: JSON-сценарий, одна UAC-проверка на пачку, журнал exit-кодов в файл (FR-4.15); HKCU-записи и пользовательские приложения — без повышения (FR-4.16).
- [ ] Обработка кодов результата: 0 и 3010 — успех; 1605/1612 — «не установлено», не ошибка; журнал (exit-код, время, ошибка); идемпотентность повторного запуска плана на уже удалённых объектах (NFR).
- [ ] Тесты: unit — типизация UninstallString и сборка команд; integration — фиктивный деинсталлятор с разными exit-кодами и таймаутом, elevated-сценарий на временных объектах.

**Когда готова:** Silent-удаление простого MSI-продукта проходит с одной UAC-проверкой на пачку; exit-код и журнал корректны; повторный запуск на записи с кодом 1605 не считается ошибкой; тесты зелёные.

### Фаза 2: Рекомендации по выбору: дубли, аномалии, размер на C:

**Цель:** Помочь пользователю выбрать объекты: дубли и старые версии как рекомендации без предвыбора, группа «Проверить вручную» для аномалий, честная оценка места на C:.

**Затрагивает:** backend

**Задачи:**
- [ ] Эвристика дублей и «старых версий»: одинаковые DisplayName/Publisher при разных версиях — рекомендация «держать последнюю, удалять старые» с пометкой версии и даты установки; никогда не предвыбор (FR-4.2).
- [ ] Пометка аномалий: пустой Publisher, `${PRODUCT_PUBLISHER}`, подозрительные домены, дата установки = дате первого запуска — группа «Проверить вручную» (FR-4.3).
- [ ] Показ «занимает на C:»: InstallLocation на C: и его фактический размер отдельно от общего размера записи (FR-4.4).
- [ ] Модель шага плана для пообъектного подтверждения: название, объём, пометка (дубль / старая версия / проверить вручную), путь (FR-4.2, FR-4.11).
- [ ] Тесты: unit — эвристики дублей и аномалий на фикстурах реестра, расчёт «занимает на C:».

**Когда готова:** На эталонной машине дубли JDK 24/26, Windows SDK, VS Build Tools 2019/2022 помечены рекомендациями без предвыбора; аномальные записи собраны в «Проверить вручную»; размер на C: показан отдельно; тесты зелёные.

### Фаза 3: Пакетные установки (bundle) и массовые MSI SDK

**Цель:** Воспроизвести сложные кейсы раздела 2 PRD: bundle (1605 → штатный uninstaller), массовое удаление MSI-компонентов SDK одной версии, «вернувшиеся» записи и зачистку каталогов/Package Cache.

**Затрагивает:** backend

**Задачи:**
- [ ] Обработка bundle: если `msiexec /x` возвращает 1605 («это не MSI») — искать исполняемый файл в `%ProgramData%\Package Cache\{code}\` и запускать с `/uninstall`; для GUI-мастеров (`winsdksetup.exe`) — ожидание завершения пользователем с таймаутом (FR-4.6).
- [ ] Массовое удаление MSI-компонентов SDK одной версии (общий DisplayVersion, например `10.1.19041.5609`): собрать все GUID и удалять последовательно `msiexec /x {GUID} /qn /norestart` с прогрессом по компонентам; суммарно ≤ 5 минут (FR-4.7, NFR).
- [ ] После деинсталляции пакета перечитывать реестр и повторно удалять компоненты, которые «вернулись» или не удалились с первого раза (реальный кейс: exit 0 при оставшихся записях) (FR-4.8).
- [ ] Удаление осиротевших каталогов версии SDK (Include/Lib/bin), если соответствующих записей в реестре больше нет (FR-4.9); очистка `Package Cache\{code}` для удалённых бандлов, если бандл больше не установлен (FR-4.14).
- [ ] Тесты: integration — фикстуры реестра и каталогов Package Cache, последовательности exit-кодов (1605/0), повторный прогон (идемпотентность), проверка, что компоненты другой версии (26100) не затрагиваются.

**Когда готова:** На эталонной машине SDK 19041 удалён полностью: реестр чист, папки Include/Lib/bin версии удалены, Package Cache очищен; компоненты версии 26100 не затронуты.

### Фаза 4: Зачистка реестра, приложения без записей, перезагрузка и подтверждения

**Цель:** Закрыть оставшиеся требования: осиротевшие записи Uninstall, удаление приложений 4DDiG-типа без записи в реестре, безопасные перезагрузка и пошаговое подтверждение с учётом зависимостей.

**Затрагивает:** backend

**Задачи:**
- [ ] Поиск осиротевших записей Uninstall (ссылаются на несуществующие пути) — отдельная группа, удаление только по подтверждению; только под `Software\Microsoft\Windows\CurrentVersion\Uninstall` и WOW6432Node; `SystemComponent=1` не трогать без явного согласия (FR-4.13).
- [ ] Удаление приложений без записи в реестре (4DDiG-типа): каталоги с проверкой процессов; Program Files/ProgramData — только с админ-правами через elevated-процесс (FR-4.10).
- [ ] Перезагрузка: запрашивать у пользователя по завершении; не выполнять `msiexec /restart` принудительно (FR-4.12).
- [ ] Пообъектное подтверждение каждого шага с объёмом и названием; предупреждение «может затронуть X» по статическому списку известных зависимостей (VS Build Tools 2019 → SDK 19041) (FR-4.11, §7).
- [ ] Тесты: unit — поиск осиротевших записей и защита SystemComponent; integration — удаление каталогов без записи с проверкой процессов, пометка «требует перезагрузки».

**Когда готова:** Осиротевшие записи Uninstall предложены отдельной группой и удаляются только по подтверждению; приложение 4DDiG-типа удаляется с проверкой процессов и админ-правами; перезагрузка только по запросу пользователя; предупреждения зависимостей формируются.

### Фаза 5: Экран деинсталляции и зачистки в GUI (frontend)

**Цель:** Пользовательский сценарий M2: выбор из списка ПО (без предвыбора), подтверждение шагов, прогресс массовой деинсталляции и инструкции для GUI-мастеров.

**Затрагивает:** frontend

**Задачи:**
- [ ] Список ПО с колонками (размер, «на C:», дата, версия, издатель, путь), фильтр дублей/старых версий и группа «Проверить вручную» (FR-4.1–4.4).
- [ ] Выбор объектов без предвыбора: дубли — рекомендация с пометкой; подтверждение каждого шага с объёмом и названием (FR-4.2, FR-4.11).
- [ ] Прогресс по компонентам при массовой деинсталляции SDK (FR-4.7); инструкция в UI «завершите мастер» для GUI-деинсталляторов с таймаутом ожидания (FR-4.11, §7).
- [ ] Запрос перезагрузки при необходимости (FR-4.12); отображение группы «Осиротевшие записи Uninstall» с подтверждением (FR-4.13).
- [ ] Тесты: unit ViewModel-ей (состояние выбора, пометки, инструкции); e2e на эталонной машине — silent-удаление CCleaner (Inno, D:) и K-Lite без GUI и без остатков записей.

**Когда готова:** Полный сценарий деинсталляции эталонной машины выполняется из GUI с подтверждениями, прогрессом и журналом; silent-удаление Inno-приложений завершается без GUI и без остатков записей; компоненты актуальных версий не затронуты.

## Критерии приёмки PRD (раздел 6) и их покрытие

- **SDK 19041 удалён полностью (реестр чист, Include/Lib/bin удалены, Package Cache очищен)** — Фазы 3–4, проверка на эталонной машине после Фазы 3.
- **Корректно различает MSI и bundle (1605 → штатный uninstaller)** — Фаза 1 (обработка кодов) + Фаза 3 (поиск exe в Package Cache).
- **Silent-удаление CCleaner и K-Lite без GUI и без остатков записей** — Фаза 1 (Inno-профиль) + Фаза 5 (e2e).
- **Ни один компонент актуальной версии (26100, текущий JDK) не затронут** — Фаза 2 (рекомендации, не предвыбор) + Фаза 3 (изоляция по DisplayVersion) + Фаза 4 (SystemComponent-защита).
