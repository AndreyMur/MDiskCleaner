# PRD 00 — DiskCleaner: Обзор продукта и дорожная карта

- **Версия:** 1.0
- **Дата:** 2026-09-06
- **Статус:** Черновик
- **Автор:** Команда продукта (на основе реально выполненной очистки диска C:)

## 1. Контекст и проблема

Диск C: системного пользователя был заполнен на 93% (135,9 ГБ из 146,9 ГБ занято, свободно 10,9 ГБ). Ручная очистка выявила и освободила ~57 ГБ. Основные источники «мусора»:

1. Кэши пакетных менеджеров и тулчейнов (npm, Gradle, pip, pnpm, uv, dotslash, Cargo) — до 30 ГБ.
2. Устаревшие/осиротевшие тулчейны и SDK (Android SDK, дубли JDK, старые версии Windows SDK).
3. Остатки после удалённых программ (папки `*-updater`, конфиги, пустые каталоги в Program Files, записи в реестре).
4. Системные файлы (hiberfil.sys, Temp, SoftwareDistribution, Корзина).
5. Неиспользуемое ПО (несколько версий одного продукта, «чистильщики», подозрительные приложения).

Пользователи не имеют инструмента, который безопасно, прозрачно и пошагово выполняет такой анализ и очистку с подтверждением каждого действия.

## 2. Цели продукта (Goals)

- G1. Автоматизировать обнаружение «мусора»: кэши, остатки, дубли, устаревшее ПО.
- G2. Предоставлять **пошаговый план очистки** с оценкой освобождаемого места для каждого шага.
- G3. Выполнять действия **только с подтверждением пользователя** (принцип «ничего не удалять молча»).
- G4. Обеспечить безопасность: предотвращать удаление используемых файлов, требовать админ-права только там, где нужно (UAC), иметь откат/отчёт.
- G5. Показывать результат: сколько места освобождено, что удалено, что осталось.

## 3. Не-цели (Out of scope)

- Не является заменой штатного деинсталлятора для конкретных программ.
- Не чистит WinSxS, не выполняет сжатие/дефрагментацию.
- Не удаляет пользовательские данные (документы, проекты, Downloads) без явного выбора.
- Версия 1.0 — Windows-only (cmd/PowerShell/API), кроссплатформенность позже.

## 4. Пользователи и сценарии

| Персона | Боль | Сценарий |
|---|---|---|
| Разработчик | Диск забит кэшами (npm, Gradle, Docker, Playwright) | Сканирует, видит топ кэшей, жмёт «Очистить» по каждому |
| Обычный пользователь | Не знает, что удалять | Жмёт «Анализ», получает понятный план «Что и почему», подтверждает |
| Системный администратор | Массовая очистка ПК | CLI-режим, JSON-отчёт, dry-run |

## 5. Архитектура решения

Десктопное приложение для Windows (v1.0), целевой стек — **.NET 8 (LTS) + C# + WPF**. GUI — тонкий слой поверх тестируемого ядра на C#; системные операции выполняются через штатные средства Windows (msiexec, powercfg, деинсталляторы) и Win32/.NET API, а не через PowerShell-обёртки.

### 5.1 Технологический стек

| Слой | Технология | Комментарий |
|---|---|---|
| Платформа | .NET 8 (LTS), C# 12, Windows-only | Один язык для GUI и ядра; LTS-поддержка |
| GUI | WPF + MVVM (CommunityToolkit.Mvvm) | Дерево категорий, DataGrid, чекбоксы, прогресс, мастер шагов |
| Сканирование диска | Параллельный обход каталогов (Win32 `FindFirstFile`/`FindNextFile` через P/Invoke); `Task`, `IProgress<T>`, `CancellationToken` | FR-1.1–1.5: скан без подвисания UI, ≤ 5 мин |
| Реестр | `Microsoft.Win32.Registry` | Чтение 3 веток Uninstall; удаление осиротевших записей (FR-1.8, FR-4.13) |
| Процессы и блокировки | `System.Diagnostics.Process`; WMI (`Win32_Process`) | Определение `IN_USE` по ExecutablePath (FR-1.7, FR-5.7) |
| Права и UAC | app.manifest (`asInvoker`) + elevated-процесс через `ProcessStartInfo.Verb = "RunAs"` | Основной процесс без прав; админ-шаги — отдельный процесс-исполнитель (FR-5.10–5.12) |
| Деинсталляция | `ProcessStartInfo` → `msiexec /x`, `unins000.exe`, `Uninstall.exe /S`; разбор exit-кодов | PRD 04: silent-режимы, обработка 1605/1612/3010, bundle-кейсы |
| Пути кэшей | Чтение конфигов менеджеров (`npm config get cache`, `.npmrc` и т.п.) | FR-2.2–2.4: фактический путь, а не дефолтный |
| Отчёты и план | `System.Text.Json`; Markdown — собственный генератор | Экспорт (FR-1.12, FR-5.16), обмен данными с elevated-процессом |
| Логирование | Serilog → `%LOCALAPPDATA%\DiskCleaner\logs\*.log` (UTF-8) | FR-5.13; UTF-8 обязателен (кейс кириллицы) |
| Тестирование | xUnit, NSubstitute; интеграционные тесты на временных каталогах | Критерии приёмки PRD 01–05 |
| Развёртывание | `PublishSingleFile` (один .exe) или MSIX | Без установщика; portable-схема для v1.0 |

### 5.2 Процессная модель и права

- Основной процесс (`DiskCleaner.exe`) — без прав администратора: UI, сканирование, реестр пользователя, составление и отображение плана.
- Админ-операции выполняет отдельный **elevated-процесс** (`DiskCleaner.Elevated.exe`), запускаемый один раз на пачку шагов через UAC (`ProcessStartInfo.Verb="RunAs"`). Он получает сценарий в JSON, исполняет и пишет журнал; основной процесс прав не наследует (FR-5.10–5.11).
- Ядро (сервисы: скан, категоризация, планировщик, исполнитель, отчёт) не зависит от WPF и покрывается unit-тестами; GUI — адаптер поверх ядра.

### 5.3 Состав приложения (модули)

1. **Анализ** (сканирование и категоризация) — PRD 01.
2. **Кэш-клинер** — PRD 02.
3. **Сканер остатков** (лефтоверы от удалённых программ) — PRD 03.
4. **Деинсталлятор** (включая пакетные SDK и реестр) — PRD 04.
5. **Системная очистка и безопасность** (Temp, гибернация, UAC, отчёты) — PRD 05.

Общие компоненты: единая модель «Объект очистки» (путь, размер, категория, риск, требуется ли админ, оценка экономии), планировщик шагов, движок выполнения с подтверждением, журнал действий.

## 6. Функциональные требования верхнего уровня

- FR-0.1: Кнопка «Анализ» запускает сканирование и строит дерево категорий с размерами.
- FR-0.2: Для каждого найденного объекта доступны: размер, риск (низкий/средний/высокий), требуется ли права администратора, что будет удалено.
- FR-0.3: Пользователь выбирает объекты и запускает «Выполнить план»; приложение спрашивает подтверждение по каждому опасному шагу и при необходимости — UAC.
- FR-0.4: По завершении формируется отчёт: освобождено N ГБ, список удалённого, ошибки/заблокированные файлы.
- FR-0.5: Режим dry-run (предпросмотр без удаления) и режим CLI (`--scan`, `--clean --category=... --yes`).

## 7. Нефункциональные требования

- Безопасность: ни одно действие не выполняется без явного согласия; удаление в Корзину для пользовательских данных (опционально).
- Производительность: полный скан диска — не дольше 5 минут; сканы кэшей — до 30 секунд; сканирование в фоне с прогрессом.
- Надёжность: при сбое/блокировке файла — пропустить, записать в журнал, не прерывать весь план.
- Локализация: RU/EN (v1.0 — RU).
- Логирование всех действий в `%LOCALAPPDATA%\DiskCleaner\logs`.
- Не запрашивать админ-права без необходимости (разделять операции пользователя и системы).

## 8. Ключевые показатели успеха

- Среднее освобождение при первом запуске у целевого пользователя: ≥ 20 ГБ.
- Доля успешных очисток без ошибок пользователя: ≥ 95%.
- Время от запуска анализа до готового плана: ≤ 3 минуты.
- Ноль удалений используемых/нужных пользовательских файлов по итогам бета-теста (критерий: ни одного инцидента в журнале беты).

|---|---|---|

## 10. Эталонный сценарий (из реальной очистки)

Описывает «золотой путь», который MVP обязан воспроизводить по шагам (детали в соответствующих PRD):

1. Скан диска → обнаружены: npm-cache 14,5 ГБ, `.gradle` 13,3 ГБ, Android SDK 14 ГБ, Playwright 2,1 ГБ, Rust 3,2 ГБ и др.
2. Категоризация: кэши (безопасно), остатки (средне), ПО на удаление (подтверждение).
3. План из шагов с суммарной оценкой ~55 ГБ.
4. Выполнение с UAC-повышением для системных шагов (отключение гибернации, деинсталляция MSI-компонентов SDK, удаление из Program Files).
5. Итог: 67,7 ГБ свободно (+57 ГБ).

## 11. Риски

- Некорректная оценка «неиспользуемости» ПО → всегда спрашивать, не предзаполнять «удалить» для программ.
- Удаление кэша → повторная загрузка при следующей сборке; предупреждать о трафике/времени.
- MSI/бандлы (Windows SDK) не удаляются простым `msiexec /x` родителя — использовать штатный uninstaller пакета (см. PRD 04).
- Файлы, заблокированные запущенными процессами (VS Code, adb) → предварительная проверка процессов (см. PRD 05).
