# Plan: DiskCleaner — Обзор продукта и дорожная карта

**PRD:** 00-Overview-and-Roadmap
**Дата:** 2026-09-06

## Согласованность с PRD

Фазы плана соответствуют майлстоунам дорожной карты M1–M4 (раздел 9 PRD). Покрываются цели G1–G5, FR-0.1–0.5, нефункциональные требования и эталонный сценарий (раздел 10). Детальные требования модулей 01–05 описаны в отдельных PRD; здесь задачи сформулированы на уровне дорожной карты.

| Фаза | Майлстоун | Модули | Критерий готовности |
|---|---|---|---|
| Фаза 1 | M1 MVP | 01 (Анализ), 02 (Кэш-клинер) | Очистка 30 ГБ кэшей на эталонной машине |
| Фаза 2 | M2 | 03 (Остатки), 04 (Деинсталлятор), UAC | Полный сценарий «эталонной очистки» |
| Фаза 3 | M3 | 05 (Система и безопасность), планировщик, Корзина-режим | Бета у 10 пользователей |
| Фаза 4 | M4 | CLI, JSON-отчёты, интеграция со штатными средствами | Чек-лист администратора |

Во всех фазах GUI остаётся тонким слоем (WPF + MVVM) поверх тестируемого ядра на C#, поэтому unit- и интеграционные тесты пишутся на ядро. v1.0 — локализация RU.

## Фазы реализации

### Фаза 1: Минимальный рабочий путь — анализ диска и очистка кэшей (M1)

**Цель:** Первый сквозной срез (Tracer Bullet): «Анализ → дерево категорий → план с оценкой → подтверждение → очистка → отчёт». Очистка кэшей пакетных менеджеров и тулчейнов на эталонной машине с высвобождением ≥ 30 ГБ.

**Затрагивает:** backend (ядро .NET/C#), frontend (GUI WPF) — модули 01–02

**Задачи:**
- [ ] Скелет решения: раздельные проекты Core (не зависит от WPF) и GUI; единая модель «Объект очистки» (путь, размер, категория, риск, админ-флаг, оценка экономии); Serilog → `%LOCALAPPDATA%\DiskCleaner\logs` (UTF-8); app.manifest (`asInvoker`).
- [ ] Модуль 01 «Анализ»: параллельный обход каталогов (P/Invoke `FindFirstFile`/`FindNextFile`); `Task`, `IProgress<T>`, `CancellationToken`; определение фактических путей кэшей по конфигам менеджеров; категоризация и построение дерева категорий с размерами (FR-0.1).
- [ ] Модуль 02 «Кэш-клинер»: обнаружение кэшей (npm, Gradle, pip, pnpm, uv, dotslash, Cargo, Playwright, Rust, Docker); для каждого объекта — размер, риск (низкий/средний/высокий), что будет удалено; предупреждение о повторной загрузке при следующей сборке (FR-0.2).
- [ ] GUI и выполнение: кнопка «Анализ» с прогрессом и отменой; дерево категорий с деталями объекта; выбор объектов чекбоксами; dry-run-предпросмотр без удаления; «Выполнить план» с подтверждением опасных шагов; отчёт «освобождено N ГБ / удалённое / ошибки и заблокированные файлы» (FR-0.3, FR-0.4, FR-0.5 — dry-run).
- [ ] Тесты: unit — категоризация и оценка рисков; интеграционные на временных каталогах — очистка кэшей, пропуск заблокированных файлов с записью в журнал без прерывания плана; e2e на эталонной машине (≥ 30 ГБ); проверка, что dry-run ничего не удаляет.

**Когда готова:** На эталонной машине полный скан ≤ 5 минут, от запуска анализа до готового плана ≤ 3 минут; выполнение с подтверждением высвобождает ≥ 30 ГБ кэшей; работают dry-run и отчёт; UI не блокируется при сканировании.

### Фаза 2: Остатки удалённых программ, деинсталлятор ПО/SDK и UAC (M2)

**Цель:** Расширить очистку на остатки удалённых программ и неиспользуемое/осиротевшее ПО и SDK (Android SDK, дубли JDK, Windows SDK) через штатные деинсталляторы; админ-операции вынести в отдельный elevated-процесс с одним UAC-подъёмом; воспроизвести полный «эталонный сценарий».

**Затрагивает:** backend (ядро, elevated-процесс), frontend (GUI), database (реестр — ветки Uninstall)

**Задачи:**
- [ ] Модуль 03 «Сканер остатков»: поиск остатков удалённых программ (папки `*-updater`, конфиги, пустые каталоги в Program Files) и осиротевших записей в 3 ветках Uninstall (`Microsoft.Win32.Registry`); размер, риск, категория; интеграция в дерево и план.
- [ ] Модуль 04 «Деинсталлятор»: инвентаризация установленного ПО из веток Uninstall; запуск штатных деинсталляторов (`msiexec /x`, `unins000.exe`, `Uninstall.exe /S`) с silent-режимами; разбор exit-кодов (1605/1612/3010); для MSI-бандлов (Windows SDK) — штатный uninstaller пакета, а не `msiexec /x` родителя; программы не предзаполнять «удалить» — всегда подтверждение.
- [ ] Elevated-процесс и UAC: `DiskCleaner.Elevated.exe` запускается с `ProcessStartInfo.Verb = "RunAs"` один раз на пачку системных шагов; обмен JSON-сценарием и журналом; основной процесс прав не наследует; UAC запрашивается только там, где нужен.
- [ ] Применение к реальному сценарию: деинсталляция MSI-компонентов SDK, удаление дублей JDK и остатков из Program Files с подтверждением по каждому опасному шагу; GUI-представление «что удалит деинсталлятор».
- [ ] Тесты: интеграционные на временных каталогах и изолированных ветках реестра (остатки, осиротевшие записи); unit — выбор деинсталлятора (включая bundle-кейсы) и разбор exit-кодов; e2e elevated-процесса на временных объектах (сценарий → исполнение → журнал).

**Когда готова:** Полный сценарий «эталонной очистки» воспроизводится — в сумме с Фазой 1 освобождено ~57 ГБ (67,7 ГБ свободно); системные шаги выполняются за один UAC-подъём; основной процесс не наследует админ-права.

### Фаза 3: Системная очистка, безопасность, планировщик и Корзина-режим (M3)

**Цель:** Закрыть системные источники мусора (Temp, SoftwareDistribution, hiberfil.sys, Корзина) с гарантией безопасности (проверка процессов и блокировок, IN_USE), добавить планировщик/расписание и Корзина-режим для пользовательских данных; выпустить бета-версию у 10 пользователей.

**Затрагивает:** backend (ядро, elevated-процесс), frontend (GUI), database (реестр пользователя/системы)

**Задачи:**
- [ ] Модуль 05 «Системная очистка»: очистка системного Temp, SoftwareDistribution, Корзины; отключение гибернации и удаление hiberfil.sys (powercfg) — админ-шаг через elevated-процесс; категории и риски в дереве/плане.
- [ ] Безопасность удаления: определение запущенных процессов (WMI `Win32_Process` по ExecutablePath), пометка объектов `IN_USE`; предварительная проверка перед удалением; заблокированные файлы — пропустить, записать в журнал, не прерывать план.
- [ ] Корзина-режим: пользовательские данные (документы, проекты, Downloads) удаляются только по явному выбору и отправляются в Корзину.
- [ ] Планировщик/расписание: запуск анализа и очистки по расписанию с сохранением принципа подтверждения (никаких «молчаливых» удалений).
- [ ] Тесты: интеграционные для Temp/Корзины на временных каталогах; тесты детектора процессов (IN_USE) и пропуска заблокированных файлов; e2e планировщика; сборка PublishSingleFile и бета у 10 пользователей — ноль удалений используемых/нужных файлов по журналу беты.

**Когда готова:** Бета-версия развёрнута у 10 пользователей; системная очистка и Корзина-режим работают; расписание запускается; по итогам беты ноль инцидентов удаления используемых/нужных файлов.

### Фаза 4: CLI-режим, JSON-отчёты и интеграция со штатными средствами (M4)

**Цель:** Дать системному администратору CLI-инструмент массовой очистки, machine-readable JSON-отчёты и надёжную интеграцию со штатными средствами Windows для автоматизации очистки ПК.

**Затрагивает:** backend (CLI на общем ядре), database (реестр)

**Задачи:**
- [x] CLI-режим: флаги `--scan`, `--clean --category=... --yes`, dry-run-предпросмотр; переиспользование ядра планирования/исполнения без GUI (FR-0.5).
- [x] JSON-отчёты (`System.Text.Json`): единая схема результата (освобождено, список удалённого, ошибки/заблокированные файлы) для отчёта GUI и CLI; корректный UTF-8.
- [x] Интеграция и автоматизация: системные шаги и silent-деинсталляция из CLI через штатные средства (msiexec, powercfg) с корректной обработкой exit-кодов и админ-подъёмом только при необходимости; журналирование в `%LOCALAPPDATA%\DiskCleaner\logs`.
- [x] Чек-лист администратора: документированный сценарий массовой очистки ПК — сухие прогоны (dry-run), повторяемость, JSON-отчёты; покрытие сценария «Системный администратор».
- [x] Тесты: e2e CLI (`--scan`; `--clean --yes` на временных объектах; dry-run ничего не удаляет); валидация JSON-схемы отчёта; прогон чек-листа администратора на эталонной машине.

**Когда готова:** Системный администратор выполняет полный цикл очистки ПК через CLI без GUI, получает JSON-отчёт и воспроизводит результат на эталонной машине; чек-лист администратора закрыт.
